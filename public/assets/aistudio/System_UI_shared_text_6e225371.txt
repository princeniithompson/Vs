Blueprint: Zero-Friction Automatic Gemini API Key Onboarding (Android / Kotlin / Jetpack Compose)
1. Objective & Product Constraints
Implement silent, zero-input Gemini API key provisioning inside a native Android app so users never have to visit Google AI Studio manually or paste an API key.
Non-Negotiable Constraints:
No Bootstrap AI Models: Do NOT use Gemini, Firebase AI Logic, or any LLM to inspect screenshots or parse pages. All page detection and clicking must run 100% locally via WebView DOM math, Find-in-Page matching, and Android MotionEvent touch synthesis.
No Password Gate: Do NOT ask the user to create or enter a vault password to view, use, or refresh their key. Store the key silently on-device using Android Keystore (AES/GCM/NoPadding) + DataStore so the app injects it into API requests automatically.
Screenshots Allowed: Do NOT enable FLAG_SECURE or ScreenCaptureCallback blackout overlays anywhere in the app.
Silent Background Retrieval During Onboarding: Users sign into their Google account (if not already authenticated) and continue granting app permissions (e.g., microphone, accessibility, notifications) while the retrieval engine silently obtains and stores the Gemini API key behind the scenes.
2. User Experience & Silent Background Architecture
Seamless Onboarding Flow
Step 1 — Google Sign-In + App Permissions:
User taps "Continue with Google" (optionally with an email hint) and signs into Google inside an embedded WebView whose cookies persist across launches.
Immediately after login (or if session cookies already exist), the user moves onto app-specific onboarding steps (e.g., granting Microphone / Accessibility permissions, picking preferences).
Step 2 — Background Key Harvester (0f Alpha Active Layout):
CRITICAL ANDROID WEBVIEW RULE: Never hide an automated WebView with View.GONE, 0.dp x 0.dp size, or detached composables. Angular SPAs and getBoundingClientRect() require real laid-out viewport dimensions to render UI elements and compute tap coordinates.
Instead, render the WebView inside a Box(Modifier.fillMaxSize()) underneath the active onboarding/permissions UI with alpha = 0f (and disable touch interception on the hidden layer so user taps always go to the foreground onboarding screen).
Auto-Surface on Auth Required: Only bring the WebView to the foreground (alpha = 1f) if isGoogleAuthUrl(url) triggers (e.g., expired cookies or 2FA prompt), then automatically return it to the silent background layer once redirected back to aistudio.google.com.
Optional Debug Toggle: Expose a simple developer/diagnostic toggle (or small status indicator) if the user wants to watch or troubleshoot the browser live, without blocking screenshots.
Step 3 — Silent Injection & Cleanup:
Once a valid key is captured from clipboard or DOM text, immediately encrypt and save it to DataStore using Android Keystore AES-256-GCM, flush CookieManager, safely destroy the WebView, and expose the decrypted key in memory/repository to your app’s Gemini client (Authorization / x-goog-api-key) without ever asking the user to paste anything.
3. Required WebView Hardening (AiStudioAutomationEngine)
Configure the WebView exactly as follows to avoid Google Sign-In blocks, blank screens, and renderer crashes:
Supported API Key Regex (Dual Format):
Google AI Studio issues both classic AIzaSy... keys and newer AQ.... keys. Validate both:
Kotlin
private val GEMINI_KEY_REGEX =
    Regex("^(AIzaSy[A-Za-z0-9_-]{28,}|AQ\\.[A-Za-z0-9_.-]{28,})$")
Layout & Rendering Settings:
layoutParams = ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)
setBackgroundColor(Color.WHITE)
setLayerType(View.LAYER_TYPE_NONE, null)
On Android O+: setRendererPriorityPolicy(WebView.RENDERER_PRIORITY_IMPORTANT, false)
WebSettings & Clean User-Agent:
javaScriptEnabled = true, domStorageEnabled = true, databaseEnabled = true
cacheMode = WebSettings.LOAD_DEFAULT, mixedContentMode = MIXED_CONTENT_COMPATIBILITY_MODE
useWideViewPort = true, loadWithOverviewMode = false
setSupportMultipleWindows(false), javaScriptCanOpenWindowsAutomatically = false
Strip ; wv token from User-Agent (critical so Google OAuth / Sign-In accepts the embedded browser):
Kotlin
val defaultUa = WebSettings.getDefaultUserAgent(webView.context)
settings.userAgentString = defaultUa.replace("; wv)", ")").replace("; wv", "")
Cookies & URL Helpers:
CookieManager.getInstance().setAcceptCookie(true) and setAcceptThirdPartyCookies(webView, true).
Login URL builder: https://accounts.google.com/ServiceLogin?continue=${Uri.encode("https://aistudio.google.com/api-keys")} (with optional &Email=...).
Intercept intent: URLs in shouldOverrideUrlLoading by extracting S.browser_fallback_url=.
Handle onRenderProcessGone and tear down cleanly (stopLoading(), loadUrl("about:blank"), detach from parent ViewGroup, removeAllViews(), destroy()).
4. Startup Warmup & Full SPA/DOM Load Detection
Google AI Studio is an Angular Single-Page Application (SPA). WebViewClient.onPageFinished and progress == 100 fire as soon as the minimal HTML shell loads—before Angular hydrates routes, terms dialogs, or key tables. Acting too early causes redirect/refresh loops.
Implement this exact startup protocol before starting element retrieval:
Wait for Initial Navigation: Poll until !isPageLoading && webView.progress >= 100.
Two-Refresh Startup Sequence (Once Per WebView Session):
If not on accounts.google.com:
Trigger Refresh 1/2 (webView.reload()), wait until !isPageLoading && webView.progress >= 100.
Pause 2.5 seconds (delay(2_500L)).
Trigger Refresh 2/2 (webView.reload()), wait until !isPageLoading && webView.progress >= 100.
Track startupRefreshCountDone per WebView instance so resuming after a pause never repeats startup refreshes.
Verify DOM & SPA Hydration (waitForPageFullyLoaded):
Run a JavaScript PageLoadReadiness probe every ~450ms and require 2 consecutive ready probes on the same settled URL before continuing:
document.readyState === "complete"
document.body.innerText.trim().length >= 35
Visible UI landmarks exist (e.g., text matches api keys, create api key, create a new key, welcome to google ai studio, continue, sign in, OR at least 1 visible interactive button, [role="button"], mat-checkbox, [role="checkbox"], or <input>).
No blocking circular loader (mat-progress-spinner, mat-spinner, [role="progressbar"] with rendered size >= 20x20) is currently visible.
5. Screen-Agnostic Find-in-Page & Coordinate Math (FindInPageController)
Because screen sizes differ across phones, foldables, and tablets, never hardcode pixel coordinates and avoid synthetic el.click() alone (Angular Material and clipboard APIs often require trusted touch gestures).
DOM + Shadow DOM Text & Accessibility Scanner:
Optionally call webView.findAllAsync(query) for visual highlighting in debug mode.
Run JavaScript walking document.body (and any open el.shadowRoot) with:
document.createTreeWalker(root, NodeFilter.SHOW_TEXT) + document.createRange().getBoundingClientRect() for visible text matches.
Querying button, [role="button"], a, [aria-label], [title], input[type="button"], input[type="submit"], [role="option"], mat-option so icon-only buttons (like Copy buttons whose label is in aria-label="Copy API key" or title="Copy") are found reliably.
Climb to clickable ancestors (button, a, [role="button"], menuitem, option, tab, combobox) and verify enabled state (disabled, aria-disabled="true", mat-mdc-button-disabled, mdc-button--disabled).
Deduplicate nearby boxes (|cx1 - cx2| < 10 && |cy1 - cy2| < 10) and filter excluded phrases (e.g., exclude "copyright" when searching "copy").
Normalized 0..1000 Viewport Coordinates:
Convert every bounding box center (cx, cy) against (window.innerWidth, window.innerHeight) into normalized 0..1000 integers:
Kotlin
fun normalizeToScale1000(position: Float, dimension: Float): Int =
    if (dimension <= 0f) 0 else ((position / dimension) * 1000f).roundToInt().coerceIn(0, 1000)
Scroll-Into-View & Re-Measure:
If !match.inViewport, execute el.scrollIntoView({ behavior: 'auto', block: 'center', inline: 'center' }), wait ~280–300ms, and re-run the measurement so coordinates match the scrolled viewport.
Real Android MotionEvent Touch Dispatch:
Convert normalized (nx, ny) back to live WebView pixels:
px = (nx / 1000f) * webView.width, py = (ny / 1000f) * webView.height.
On Dispatchers.Main, dispatch MotionEvent.ACTION_DOWN -> delay(45L) -> MotionEvent.ACTION_UP directly via webView.dispatchTouchEvent(...).
6. Multi-Bridge Auto-Retrieval State Machine
Run up to 12 cycles. At the top of every cycle, wait for !isPageLoading and waitForPageFullyLoaded(...), then check:
Auth Check: If isGoogleAuthUrl(currentUrl), pause automation and surface the WebView so the user signs in; automatically resume once redirected back to AI Studio.
Key Check (checkKeyNow()):
Read ClipboardManager.primaryClip and validate against GEMINI_KEY_REGEX.
Also scan document.body.innerText via JS for GEMINI_KEY_REGEX (in case a modal displays the newly created key in plaintext).
If found: encrypt & persist silently, clear/scrub temporary clipboard if desired, destroy WebView, and mark onboarding key ready.
Bridge A — Welcome / Terms Checkboxes & Continue (New Accounts):
Scan mat-checkbox, [role="checkbox"], input[type="checkbox"], targeting the inner box rect (.mdc-checkbox__background, .mdc-checkbox, input[type="checkbox"]).
Identify required unchecked boxes (required, aria-required="true", or label containing *, "18 years", "acknowledge", "agree", "terms"), or fallback to the first unchecked box if the "continue" button is disabled.
Scroll each required box into view, tap via MotionEvent, wait ~450ms, then locate "continue" (interactive) and tap it if !isDisabled.
Bridge B — Settled Route Guard (Anti-Loop):
If isAiStudioUrl(url) and URL does not contain "api-keys" or "apikey":
Wait ~900ms in case Angular router is mid-transition, then re-check the URL.
Look for an interactive "get api key" button and tap it (capped at 2 taps).
Otherwise allow at most 1 fallback loadUrl("https://aistudio.google.com/api-keys") per run. Never reload in an unbounded loop.
Bridge C — Existing Keys ("copy" with Fallback Across 1..N):
Find interactive matches for "copy" excluding "copyright".
Iterate indices 0..size-1: scroll match into view, re-measure, dispatch MotionEvent tap, wait ~1.15s, and call checkKeyNow().
Stop immediately on the first valid key; only move to match 2..N if the current button yielded no key.
Bridge D — Create-Key Modal Completion:
Find visible text <input> / <textarea> (excluding project search inputs). If empty, populate a default key name (e.g., your app’s name) using the native prototype value setter + dispatch Event('input', { bubbles: true }) and Event('change', { bubbles: true }) so Angular Reactive Forms detects the change:
JavaScript
var proto = el.tagName === 'TEXTAREA' ? HTMLTextAreaElement.prototype : HTMLInputElement.prototype;
var setter = Object.getOwnPropertyDescriptor(proto, 'value');
if (setter && setter.set) setter.set.call(el, keyName); else el.value = keyName;
el.dispatchEvent(new Event('input', { bubbles: true }));
el.dispatchEvent(new Event('change', { bubbles: true }));
If "select a cloud project" interactive dropdown is present, tap it, wait ~700ms, find the first visible mat-option, [role="option"], and tap it.
Find interactive "create key" (excluding "create a new key" and "create api key"), scroll into view, verify !isDisabled, and tap it via MotionEvent.
Bridge E — Zero Keys ("create api key"):
Find interactive "create api key", scroll into view, and tap via MotionEvent. Next cycle will enter Bridge D (fill name / pick project / create) and then Bridge C (copy) or plain-text modal scan.
Viewport Scroll Fallback:
If cycles 1–2 find none of Bridges A–E, dispatch a vertical MotionEvent swipe down (0.72 * height -> 0.28 * height) in case buttons are below the fold.
7. Checklist for the Implementing Agent

Keep WebView laid out at full viewport size behind onboarding (alpha = 0f, non-intercepting when hidden), surfacing only for Google Sign-In (accounts.google.com) or optional diagnostics.

Strip ; wv from User-Agent and enable third-party cookies.

Run the 2-refresh startup sequence + 2-probe PageLoadReadiness SPA check before touching DOM elements.

Use normalized 0..1000 coordinates + scrollIntoView + MotionEvent taps (plus Angular native property setter for inputs).

Accept both AIzaSy... and AQ.... Gemini API key formats.

Store the retrieved key silently via Keystore AES-256-GCM + DataStore with no password prompts and no screenshot restrictions.
